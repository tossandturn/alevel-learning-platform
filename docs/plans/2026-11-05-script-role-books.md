# 角色本补全

用户澄清：入口存在，问题是背景只有几句话，没有代入感。停止把这次需求当作导航缺陷；不为此再发一个只改布局的客户端。

## 实施范围

- 四个原有原创剧本、16个角色，每人一份约850–2600字符的入场角色本。篇幅不是唯一验收指标：必须有具体场景、人生转折、矛盾动机、三位同场人物的个人认识、来到此处的原因及可选开场行动。
- 使用第二人称“你”让玩家代入自己的角色。关系描述是角色的观察，不是对别人秘密或内心的全知描述；可选发言不冒充玩家已经说过。
- 原真相、物证、时间线、机关答案、投票与个人决定不改。以后幕的发现仍由规则引擎解锁，不提前塞进阅读本。
- 后端展示层将角色本放到已有私有 biography 字段，兼容正在运行的v1/v2房间和现有小程序。旧原始剧本数据保持冻结；公共角色列表、目录和邀请里不放角色本。
- 对应AI演员接收相同的自己角色本；主持人、其他演员、图片生成与其他产品不接收此人的私有背景。
- 本次不新增登录门槛、不改会员、不生成音频、不改模型；无必要不发新客户端。

## 验证顺序

1. 测试先证实原背景过短；补作者内容和受权限控制的投影。
2. 逐角色校对关系与现有秘密，不用泛用模板灌水，也不新增核心物证。
3. 测试32个v1/v2角色投影、公共/私人隔离、原房间规则与模型上下文；原生身份页检查长文排版。
4. 后端代码与完整剧本相关测试通过后，按独立服务器只读资源门槛进行最小允许列表发布；保留可核验回滚包。不做生产源码构建。
5. 用合成鉴权账号验证在线身份文本及一段背景追问，记录上线与真机未验收边界。
