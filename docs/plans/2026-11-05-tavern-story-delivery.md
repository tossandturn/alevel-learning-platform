# 普通酒馆叙事与输入修复

用户截图是普通酒馆“江湖剑客”(`xianxia-guide`)，不是多人剧本杀。此次不继续改剧本杀身份卡。

## 已复核原因

- 客户端两列输入网格新增了未跨列的画图提示，提示、textarea、发送三个元素按自动网格排位；因此textarea落在72px按钮列，发送落在下一行。
- 故事角色始终同时收到简短闲聊、80–180字场景、人物经历与互动规则。没有逐轮区分讲往事、修改叙事、普通闲聊；反馈被当成另一轮短闲聊。
- 宽泛的“开始/继续/剧情”匹配会把上班闲聊、否定句、修辞反馈误当成故事开始；“检查某物写得无聊”也可能误计线索。

## 范围与约束

1. 输入固定为输入区和发送两列；画图说明移入空对话引导，不常驻底栏。塔罗工具保留跨列；键盘、失败重试、草稿和账号隔离不变。
2. 每轮明确chat / memory / scene / repair表达模式，保留于已有服务端进度元数据。表达模式不能解锁线索、揭晓真相或替玩家行动。
3. 讲往事有具体目标、阻力、行动及后果；反馈要求改善因果与事件，不只道歉、加口癖或改小动作。不把“无聊”改成新阴谋或重开主线。
4. 四种故事给公开的戏剧冲突框架，事实和最终真相仍来自原规则；禁止任意改写已确认内容。普通日常仍简短，暂停被尊重。
5. 原生模拟器先复现截图布局，再验证故事/普通/占卜、键盘与短高度；真实线上对话至少覆盖截图反馈和正常继续。不以提示词存在冒充体验通过。
