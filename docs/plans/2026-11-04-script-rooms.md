# AI 剧本杀：四本、1–4 人、服务端裁决

日期：2026-11-04（Windows 本机 Asia/Shanghai）。用户提供的两张架构图作为本次设计依据。

## 交付边界

- 酒馆中的独立原生模式，不替换原有自由聊天；浏览无需强制登录，创建/加入房间需现有账号。协议默认不勾选。
- 四本原创完整短剧本：情感《雨停之前》、推理《第十三次落幕》、恐怖逃脱《零点末班车》、密室解谜《倒悬天文馆》。每本固定四角色，1–4 真人，其余 AI 补位；不做陌生人匹配、投注、红包、付费抽取或玩家交易。
- 每本有三幕、12 条有归属与解锁阶段的线索、个人目标、共同目标、阶段谜题/抉择、最终投票与复盘。人物秘密、时间线、谜底仅在服务器；通用聊天不得修改它们。
- 邀请链接/房间码、选角准备、公开聊天、两人私聊、AI 角色对话、搜证公开、任务面板、投票、断线恢复、主动离席/AI 托管、房主移交。
- 已生成场景图复用作对应章节气氛插图，不作解谜关键证据。谜题必要文字永远提供文本，不要求看图辨认密码。

## 三种技术选择与决定

1. 推荐且采用：现有 Node + SQLite 的独立有权威状态房间。短轮询适配微信现有 request 域名，避免新增 socket 白名单；事务保证并发，快照+事件流恢复。
2. 引入 boardgame.io：隐私视图与回合成熟，但客户端/持久化适配成本大。本版只借鉴概念，不复制代码或引入依赖。
3. 纯提示词多人群聊：无法可靠隔离秘密或裁决任务，不采用。

## 权限与执行顺序

所有客户端行动携带幂等 ID 和期望 revision。事务内检查：身份、房间成员、有效期、阶段、角色归属、线索解锁和投票资格；通过后更新快照与事件。重复请求返回当前权限视图，不重复推进。房间码只允许入场，不授权读成员隐私。

AI 只取得自己角色和该对话渠道可见的证据/记忆。主持人只取得当前已公开的剧情，不提前取得最终真相；文本生成不执行任意函数。AI 提议仅有当前角色合法的公开线索/发言操作；服务端重验后才生效。模型失败不丢玩家消息、不跳幕，允许同任务重试。AI 发言和旁白分开标记，不能替真人发言。

持久化独立 script-rooms.sqlite，事务保留房间、座位、NPC 记忆、双向关系、行动事件和幂等收据；与学习/付费数据隔离。每个账号最多3间活跃房，房间72小时过期，限制消息/房间/事件大小；只返回本人身份卡、授权私聊和公开记录。用户可主动退出；最后真人退出关闭房间。

## 界面

沿用产品浅色+紫色 token，剧本封面/章节图突出氛围。手机单栏：章节目标→公共/私聊→行动栏；身份/证据独立面板。iPad 限宽双栏。输入框使用页面流布局与原生键盘上推，不覆盖聊天。显示真人/AI/暂离与同步状态；错误保留输入。

## 验收

每本1人和4人完整通关；2/3人AI补位；重复/并发行动；跨房/跨账号私密隔离；抢角色/开始权限；不能跳幕/提前揭底；模型注入/超时；离席/房主转移；重启恢复；邀请登录后返回；375px手机与平板布局。单元/模拟通过不冒充真机多人验收。
